# 프로토콜 미확정 사항

제안서의 프로토콜(슬라이드 7~12)을 구현 기준으로 다시 읽으면서, 정의가 빠졌거나 두 가지로 읽히는 부분을 모았습니다. 서버와 클라이언트가 같은 규칙으로 구현하려면 코드를 쓰기 전에 정해야 합니다.

- 담당 번호는 역할표 기준입니다: 1번 서버 코어·방 관리, 2번 주문·마감, 3번 연결·세션, 4번 클라이언트, 5번 프로토콜·테스트
- **제안**은 초안입니다. 팀에서 정하면 **결정**란에 적고 표의 상태를 "확정"으로 바꿔 주세요.

| # | 항목 | 관련 담당 | 상태 |
|---|---|---|---|
| 1 | 형식 오류용 에러 코드 | 5번 | 미정 |
| 2 | ORDER/CANCEL 성공 응답 | 2번, 5번 | 미정 |
| 3 | CREATE 후 MENU·STATUS 전송 | 1번, 2번 | 미정 |

| 5 | 방장 연결이 끊긴 경우 | 3번, 1번 | 미정 |
| 6 | 마감 뒤 LEAVE 시 주문 처리 | 1번, 2번 | 미정 |

## 1. 형식 오류용 에러 코드가 없음
- **관련 담당:** 5번 (형식 검증, 오류 코드)
- **현재 정의:** 에러 코드 10종(슬라이드 11)은 형식은 맞지만 규칙에 어긋나는 요청만 다룹니다.
- **문제:** 모르는 명령(`HELLO`), 필드 부족(`JOIN|1`), 숫자가 아닌 방 번호(`JOIN|abc|Amy`)를 받았을 때 보낼 코드가 없습니다.
- **제안:** `ERR|BAD_REQUEST`를 추가합니다. 서버는 이 응답을 보낸 뒤에도 연결을 끊지 않습니다.

## 2. ORDER/CANCEL 성공 시 요청자에게 OK를 보내는지
- **관련 담당:** 2번 (주문), 5번 (응답 형식)
- **현재 정의:** 슬라이드 7은 `ORDER|1:2`에 대해 방 전체에 `STATUS`만 보냅니다. 슬라이드 10은 성공 응답을 `OK|command|...`로 정의합니다.
- **문제:** 요청자가 `OK|ORDER`를 따로 받는지에 따라 클라이언트의 수신 처리가 달라집니다.
- **제안:** "모든 요청은 `OK` 또는 `ERR` 중 하나를 받는다"로 통일합니다. 요청자는 `OK|ORDER`를 받고, 이어서 방 전체가 `STATUS`를 받습니다. CANCEL·CLEAR·CLOSE도 같은 규칙을 따릅니다.

## 3. CREATE 후 방장에게도 MENU·STATUS를 보내는지
- **관련 담당:** 1번 (방 생성), 2번 (메뉴 조회)
- **현재 정의:** JOIN은 `OK|JOIN|token` 다음에 MENU와 STATUS를 보냅니다(슬라이드 7, 9). CREATE는 `OK|CREATE|roomID|token`만 있습니다.
- **문제:** 방장도 주문하려면 메뉴가 필요합니다.
- **제안:** CREATE도 `OK|CREATE|roomID|token` 다음에 MENU와 STATUS(빈 상태)를 보냅니다.

## 4. STATUS에서 한 사람이 여러 메뉴를 주문한 경우의 표기
- **관련 담당:** 5번 (직렬화), 2번 (집계)
- **현재 정의:** `STATUS|A:1:2,B:3:1|1:2,3:1|55000` (사용자별 주문, 메뉴별 수량, 합계 순서)
- **문제:** A가 1번 메뉴 2개와 3번 메뉴 1개를 주문하면 `A:1:2,3:1,B:3:1`이 되어, `3:1`이 누구 것인지 형식만으로는 알 수 없습니다.
- **제안:** (사용자, 메뉴) 쌍마다 항목을 하나씩 씁니다.
  `STATUS|A:1:2,A:3:1,B:3:1|1:2,3:2|74000`
- **함께 정할 것:**
  - 주문이 하나도 없을 때의 표기 (예: `STATUS|||0`)
  - 주문하지 않은 참가자도 STATUS에 넣을지

## 5. 방장이 LEAVE 없이 연결이 끊긴 경우
- **관련 담당:** 3번 (연결 종료 정리, 유예 시간), 1번 (방장 관리)
- **현재 정의:** 방장이 LEAVE하면 ROOM_END입니다(슬라이드 9). 연결이 끊긴 경우는 정의가 없고, 확장 기능으로 60초 안 토큰 재접속이 있습니다(슬라이드 13).
- **문제:** 끊기자마자 방을 없애면 방장이 재접속해도 돌아갈 방이 없습니다.
- **제안:**
  - 기본 기능 단계: 연결이 끊기면 LEAVE와 같이 처리합니다 (방장이면 ROOM_END).
  - 재접속 확장 단계: 60초 동안 방과 주문을 그대로 두고, 그 안에 돌아오지 않으면 LEAVE로 처리합니다. 멤버도 같은 규칙을 따릅니다.

## 6. 마감(CLOSE) 뒤 멤버가 LEAVE하면 주문을 지우는지
- **관련 담당:** 1번 (퇴장), 2번 (마감)
- **현재 정의:** LEAVE는 마감 뒤에도 허용되고, 멤버가 나가면 그 주문을 지웁니다(슬라이드 9).

- **제안:** 마감 뒤 LEAVE는 사람만 나가고, 주문은 FINAL 그대로 둡니다.
