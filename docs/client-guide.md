# Order Together 클라이언트 안내 (팀원 확인용)

작성: 4번 남승우 (클라이언트) · 2026-11-26

## 1. 한눈에 보기

**담당:** 4번 남승우 · **코드:** `src/client/` (파일 7개) · **시작 파일:** `client.ClientMain`

클라이언트는 사용자가 방을 만들고 주문하면 서버에 메시지를 보내고, 서버가 보내는 알림(주문 현황, 마감 등)을 받아 화면에 보여 줍니다. 방장 확인, 마감 확인, 금액 계산 같은 **규칙 판단은 하지 않고** 서버 결과를 그대로 보여 줍니다.

### 실행

```
build.cmd            (PowerShell에서는 .\build.cmd)
java -cp out client.ClientMain 127.0.0.1 5050
```

- 인자를 안 주면 `serverinfo.dat`(`host=`, `port=`)을 읽고, 그것도 없으면 `127.0.0.1:5050`으로 접속합니다.
- 다른 PC의 서버에 붙을 때는 `127.0.0.1` 자리에 서버 PC의 IP를 넣습니다.

### 사용 방법 (번호 메뉴)

| 화면 | 1 | 2 | 3 | 4 | 5 | 6 | 0 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 로비 | 방 목록 | 방 만들기 | 방 들어가기 | 닉네임 바꾸기 | | | 종료 |
| 방 안 | 메뉴판 | 주문하기 | 내 주문 취소 | 방 나가기 | [방장] 전체 초기화 | [방장] 주문 마감 | 종료 |

- 번호를 누르면 필요한 값(방 이름, 방 번호, 주문 내용)을 다음에 물어봅니다. 그만두려면 `취소`를 입력합니다.
- 명령어로 바로 쳐도 됩니다. 예: `create 치킨방`, `join 1`, `order 1:2,3:1`, `cancel`, `close`. 번호와 명령어는 같은 코드를 거쳐 같은 메시지를 보냅니다.

### 구조

- **스레드 2개:** 입력 스레드(키보드 → 서버로 보내기)와 수신 스레드(서버 메시지 → 화면). 아무것도 치지 않아도 다른 사람 주문이 바로 보이는 이유입니다.
- **synchronized 3곳:** 화면 출력(`ConsoleView`), 상태(`ClientState`), 전송(`ServerConnection.send`).

| 파일 | 역할 |
| --- | --- |
| `ClientMain` | 시작점, 입력 스레드, 번호 메뉴 |
| `ReceiverThread` | 수신 스레드, 서버 메시지를 종류별로 처리 |
| `ConsoleView` | 화면 출력, 서버 메시지를 문장으로 바꾸기 |
| `ClientState` | 현재 방, 방장 여부, 메뉴판 등 상태 |
| `ClientProtocol` | 메시지 만들기·자르기, 이름 검사 |
| `ServerConnection` | 소켓 연결, UTF-8 송수신 |
| `MenuItem` | 메뉴 한 개(번호, 이름, 가격) |

## 2. 메시지 약속표

서버를 만들 때 이 표의 모양대로 보내고 받으면 클라이언트와 바로 맞습니다.

### 클라이언트 → 서버

| 언제 | 보내는 메시지 |
| --- | --- |
| 처음 접속, 로비로 돌아왔을 때, 방 목록 보기 | `ROOMS` |
| 방 만들기 | `CREATE\|닉네임\|방이름` |
| 방 들어가기 | `JOIN\|방번호\|닉네임` |
| 주문 (내 주문을 통째로 바꿈) | `ORDER\|1:2,3:1` |
| 내 주문 취소 | `CANCEL` |
| [방장] 전체 초기화 / 마감 | `CLEAR` / `CLOSE` |
| 방 나가기 (방 안에서 종료하면 자동으로 보냄) | `LEAVE` |
| 서버가 `PING`을 보냈을 때 | `PONG` |

- 닉네임 바꾸기는 서버에 아무것도 보내지 않습니다. 다음 `CREATE`나 `JOIN`에 새 이름이 실립니다.
- 클라이언트는 이름이 비었거나 `|` `,` `:`가 들어 있으면 보내지 않습니다. 주문 형식(숫자인지, 수량이 1 이상인지)도 미리 검사합니다.
- 방장인지, 마감됐는지는 검사하지 않고 그대로 보냅니다. 서버가 판단해서 `ERR`로 거절해 주세요.

### 서버 → 클라이언트 (클라이언트가 기대하는 모양)

| 메시지 | 모양 | 클라이언트 처리 |
| --- | --- | --- |
| 방 만들기 성공 | `OK\|CREATE\|방번호\|토큰` | 방 안 화면으로, 방장 표시 |
| 들어가기 성공 | `OK\|JOIN\|토큰` | `join` 때 기억해 둔 방 번호로 들어감 |
| 그 밖의 성공 | `OK\|ORDER`, `OK\|CANCEL`, `OK\|CLEAR`, `OK\|CLOSE`, `OK\|LEAVE` | 와도 되고 안 와도 됨 (안내 문장만 출력) |
| 오류 | `ERR\|코드` | 코드를 한국어 문장으로 출력 |
| 방 목록 | `ROOM_LIST\|1:치킨방:3/5:OPEN,2:피자방:5/5:CLOSED` (방이 없으면 `ROOM_LIST\|`) | 로비에 있을 때만 출력 |
| 메뉴판 | `MENU\|1:후라이드:18000,2:양념:19000` | 저장하고 출력 |
| 주문 현황 | `STATUS\|A:1:2,A:3:1,B:3:1\|1:2,3:2\|74000` (주문이 없으면 `STATUS\|\|\|0`) | 사람별로 묶어 현황표 출력 |
| 마감 | `FINAL\|`과 STATUS와 같은 3칸 | 마감 상태로 바꾸고 최종표 출력 |
| 방 종료 | `ROOM_END` | 로비로 돌아가 방 목록을 다시 요청 |
| 연결 확인 | `PING` | 바로 `PONG` |

### 오류 코드

클라이언트가 한국어 문장을 준비해 둔 코드는 `ALREADY_IN_ROOM`, `NOT_IN_ROOM`, `NO_ROOM`, `ROOM_FULL`, `DUP_NICK`, `INVALID_NAME`, `INVALID_MENU`, `NOT_HOST`, `CLOSED`, `INVALID_TOKEN`입니다. 그 밖의 코드는 "요청이 거절되었습니다. (코드)"로 보여 줍니다.

### 공통 규칙

- 한 줄이 메시지 하나이고, 끝은 `\n` 하나입니다. Windows의 `println`은 `\r\n`을 붙이므로 `print(msg + "\n")`을 권장합니다.
- 글자는 UTF-8로 주고받습니다. 닉네임과 메뉴 이름이 한글이기 때문입니다.
- 칸은 `|`, 항목은 `,`, 항목 안의 값은 `:`로 나눕니다.

## 3. 담당별 확인 목록

정해진 항목은 이 파일에서 `- [ ]`를 `- [x]`로 고쳐 주세요. 의견은 PR 댓글로 남겨 주시면 됩니다. 괄호 안의 "미확정 N번"은 [protocol-open-issues.md](protocol-open-issues.md)의 항목 번호입니다.

### 1번 · 서버 코어·방 관리

- [ ] 서버를 `java -cp out server.ServerMain 5050`으로 실행 (README와 같음)
- [ ] `CREATE` 성공 뒤 `MENU`와 빈 `STATUS`도 보내기. 안 보내면 방장 화면에 메뉴판이 없습니다. (미확정 3번)
- [ ] `JOIN` 성공 시 `OK|JOIN|토큰` → `MENU` → `STATUS` 순서로 보내기
- [ ] `ROOM_LIST` 모양 확인, 방이 생기거나 없어질 때 로비에 있는 사람에게 자동으로 보낼지 정하기
- [ ] 방장이 `LEAVE`하면 남은 사람 전원에게 `ROOM_END` 보내기
- [ ] 방 번호는 다시 쓰지 않기. 오래된 목록을 보고 `join` 해도 엉뚱한 방에 들어가지 않게 하려는 것입니다.
- [ ] 같은 방에 같은 닉네임이면 `ERR|DUP_NICK`. 그 밖에 `ROOM_FULL`, `NO_ROOM`, `ALREADY_IN_ROOM`, `NOT_IN_ROOM`, `INVALID_NAME`

### 2번 · 주문·마감

- [ ] `ORDER`는 내 주문을 통째로 바꾸기 (같은 요청이 두 번 와도 결과가 같음)
- [ ] 주문 성공 시 `OK|ORDER`를 보낼지 정하기. 클라이언트는 어느 쪽이든 됩니다. (미확정 2번)
- [ ] `STATUS` 사람별 칸은 (사람, 메뉴)마다 한 항목: `A:1:2,A:3:1,B:3:1` (미확정 4번)
- [ ] 주문이 없으면 `STATUS|||0`, 주문하지 않은 사람은 넣지 않기
- [ ] 총금액은 서버가 계산 (클라이언트는 받은 값만 보여 줌)
- [ ] `CLOSE` → 전원에게 `FINAL`, 마감 뒤의 `ORDER`·`CANCEL`·`CLEAR`는 `ERR|CLOSED`
- [ ] 방장이 아닌 사람의 `CLEAR`·`CLOSE`는 `ERR|NOT_HOST`, 없는 메뉴나 잘못된 수량은 `ERR|INVALID_MENU`
- [ ] 마감 뒤 나가는 사람의 주문은 그대로 두기 (미확정 6번)

### 3번 · 연결·세션

- [ ] `PING`을 쓸지 정하기. 클라이언트는 받으면 바로 `PONG`으로 답합니다.
- [ ] 방장이 `LEAVE` 없이 끊기면, 기본 단계에서는 `LEAVE`처럼 처리해서 `ROOM_END` (미확정 5번)
- [ ] 클라이언트가 끊기면 그 사람을 방에서 정리하기
- [ ] 재접속(`RECONNECT|토큰`)을 할지와 일정 정하기. 하기로 하면 클라이언트에 재접속 기능을 추가해야 합니다. 토큰은 이미 저장하고 있습니다.

### 5번 · 프로토콜·테스트

- [ ] 공통 파서가 나오면 `ClientProtocol` 안쪽만 그 파서를 부르게 바꾸기 (다른 파일은 그대로)
- [ ] 형식 오류 코드(`ERR|BAD_REQUEST`)가 정해지면 클라이언트에 안내 문장 추가 (미확정 1번)
- [ ] 이름 규칙 맞추기: 빈 이름 금지, `|` `,` `:` 금지, 길이 제한을 둘지
- [ ] 클라이언트 테스트용 가짜 서버(FakeServer)와 5장 시나리오를 공용 테스트로 쓸지. 저장소에 넣으면 빌드 스크립트 `ENTRIES`에 추가해야 합니다.

## 5. 같이 테스트하기

### 서버가 완성되기 전

4번이 가진 테스트용 가짜 서버(FakeServer, 5050 포트)로 클라이언트를 먼저 시험할 수 있습니다. 위 약속표대로 응답하도록 만들어 뒀으니, 서버 동작을 정할 때 참고용으로도 볼 수 있습니다.

### 진짜 서버와 함께

1. 서버 코드와 클라이언트 코드를 같이 받고 `build.cmd`
2. 창 1: `java -cp out server.ServerMain 5050`
3. 창 2, 3: `java -cp out client.ClientMain 127.0.0.1 5050`

### 확인 시나리오

| 순서 | 창 | 입력 | 기대 결과 | 관련 담당 |
| --- | --- | --- | --- | --- |
| 1 | A | 닉네임 `철수` → `2` → `치킨방` | 방이 만들어지고 메뉴판과 빈 현황이 나옴 | 1번 |
| 2 | B | 닉네임 `철수` → `3` → `1` | "같은 닉네임이 이미 있습니다" | 1번 |
| 3 | B | `4` → `영희` → `3` → `1` | 1번 방에 들어가고 메뉴판과 현황이 나옴 | 1번 |
| 4 | B | `2` → `3:1` | **A와 B 모두** 현황표가 바뀜 | 2번 |
| 5 | B | `6` | "방장만 할 수 있는 기능입니다" | 2번 |
| 6 | A | `2` → `1:2` → `6` | A와 B 모두 최종 주문표 | 2번 |
| 7 | B | `2` → `1:1` | "이미 마감된 주문입니다" | 2번 |
| 8 | A | `0` (종료) | B에 방 종료 안내가 뜨고 로비로 돌아감 | 1번 |
| 9 | 서버 | `Ctrl + C` | 클라이언트에 "서버와 연결이 끊어졌습니다" | 3번 |

### 문제가 생기면

- 클라이언트는 모르는 메시지를 받으면 `(알 수 없는 메시지) 받은 줄`로 그대로 보여 줍니다. 서버가 무엇을 보냈는지 바로 확인할 수 있습니다.
- 상황과 화면 캡처를 함께 4번(남승우)에게 알려 주세요. 클라이언트 쪽 문제인지 서버 쪽 문제인지 같이 나눠 보겠습니다.
